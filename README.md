# bytecode-optimizer-go

一套面向简单栈式虚拟机（SVM）字节码的优化管线。它解析文本字节码、在
参考解释器上执行、运行可组合的优化遍直到结果稳定，并保证优化后程序在
参考解释器上的**可观测行为与原程序完全一致**；任何非法输入或优化内部
失败都会**整体回退到原始字节码**并给出可区分的失败原因。

## 目录结构

| 路径 | 作用 |
| --- | --- |
| `pkg/ir` | 指令集、程序结构、规范文本格式、共享运算语义 |
| `pkg/parse` | 文本字节码解析（带行号与错误位置） |
| `pkg/interp` | 参考解释器（单步 trace、运行时异常带源行） |
| `pkg/opt` | 合法性/栈深度校验、四个优化遍、固定点管线、统计与回退 |
| `cmd/optbc` | 命令行：`parse` / `run` / `opt` |
| `examples` | 示例字节码 |

## 字节码格式

程序由若干函数组成，函数由 `func 名字(参数...)` 开始、`end` 结束；
以行首 `名字:` 定义跳转标号；`#` 起始为注释。

| 指令 | 栈效应 | 语义 |
| --- | --- | --- |
| `PUSH n` | +1 | 压入 64 位整数常量 |
| `LOAD x` / `STORE x` | +1 / -1 | 读/写局部变量（未写为 0） |
| `POP` | -1 | 弹出并丢弃 |
| `ADD SUB MUL DIV MOD EQ LT GT` | -1 | 弹出 b、a，压入 `a op b`（比较得 0/1） |
| `NEG` | 0 | 栈顶取负 |
| `JMP L` / `JZ L` / `JNZ L` | 0 / -1 / -1 | 无条件跳转；为零/非零跳转 |
| `CALL f k` | 1-k | 弹出 k 个参数，压入返回值 |
| `RET` | -1 | 弹出栈顶作为返回值（空栈返回 0） |
| `PRINT` | -1 | 输出栈顶并换行 |

算术是 **int64 回绕运算**；`DIV`/`MOD` 的除数为 0 时抛出带源行的
运行时异常。优化器与解释器共用 `ir.EvalBinary`，因此折叠与执行的运算
结果逐位一致（含溢出回绕）。

## 优化安全语义

管线对**原程序的克隆**工作，先 `Validate`、每个 pass 后再次 `Validate`，
最终达到不动点后才输出。任一步骤失败都返回**原指针、原内容**，并在
`Report` 中给出 `invalid_input` 或 `internal_error` 的失败类别与原因。

各遍可以独立启用，也可以任意组合（CLI 用 `-passes`，库用 `Config`）。

### 各遍与适用条件

1. **`constfold` 常量折叠**
   `PUSH a; PUSH b; <二元运算>` → `PUSH (a op b)`。
   - 共享解释器运算，溢出回绕一致；
   - **永不折叠字面量除数为 0** 的 `DIV`/`MOD`（那是运行时异常）；
   - 结果指令挂在运算符的源行上（表达式值的来源）。

2. **`peephole` 冗余指令合并**（仅允许净栈效应为 0 的规则，且不跨标号）
   - `LOAD x; STORE x` → 删除（读回写，栈与变量均不变）；
   - `PUSH c; POP` → 删除；
   - `NEG; NEG` → 删除（两次运行时取负，对最小 int64 也恒等）。
   - **刻意不做** `PUSH 0; ADD`、`PUSH 1; MUL` 之类：删除这两条会消费栈
     上的左操作数，等价性需要一条 `DUP` 指令才能成立，而本 ISA 没有
     `DUP`。这类表达式只能由常量折叠在两个操作数都是字面量时处理。

3. **`jump` 跳转链折叠**
   - `JMP A`（A 处立即 `JMP B`，中间允许标号）重写为 `JMP B`，条件跳转
     同样沿链解析；
   - 删除「目标恰好是紧随其后的标号」的冗余 `JMP`；
   - 全程以**符号标号**为目标，不做任何数值地址补丁，因此删除/插入指令
     不可能造成目标错位。

4. **`dce` 死代码消除**
   从函数入口做控制流可达性分析（标号透明，`RET`/`JMP` 终止顺序流，
   `JZ`/`JNZ` 同时产生分支与顺序边），删除所有不可达指令，并一并删除
   没有任何可达跳转引用的标号。可达性事实在同一趟内一次算清，因此本遍
   对自身输出重复运行不会再删除任何指令。函数体永远不会被删空：当函数
   只剩无引用标号时保留入口指令，保证输出仍是合法程序。

### 栈深度与异常行为

`Validate` 对控制流图做数据流分析：每个可达 PC 必须有唯一一致的栈深度，
深度不允许为负；同时校验标号定义、跳转目标、函数存在性与调用元数。
每个 pass 的产物都重新通过该校验，因此**重定位后的栈深度映射精确保持**。
运行时异常（除零等）的源行随指令保留，优化后在相同执行点仍抛出相同错误。

### 调试信息

每条指令携带 `SrcLine`（1 起，原文件行号），函数参数名完整保留。所有
变换要么删除指令、要么把结果挂到参与计算的源行上，绝不引入新的源位置。
优化后单步执行的源行序列是原序列的**子序列**，因此断点仍在原语义位置命中。

### 不动点

管线按固定 pass 顺序反复执行，直到**一整轮中所有启用的 pass 都没有产生
任何改动**（删除数与重写数均为零），最多 64 轮；无法收敛视为内部错误并
回退。收敛判定只依据循环内各 pass 的统计：达到不动点后不再做任何额外
变换（包括标号剪枝——它已并入 `dce` 在循环内完成），因此**对外输出的
程序就是各 pass 共同的不动点**。

`Report.Stable` 的含义是"返回的输出已经是真正的不动点"：把它再次作为
输入运行完整管线，输出逐字节不变、`Iterations` 为 1、所有删除统计为 0。
发生过内容变化的运行一定 `Iterations >= 2`（先观察到变化，再观察到一整
轮无变化）；未发生变化的运行一定 `Iterations == 1` 且 `TotalRemoved == 0`。
这就是不动点的验证方法：对输出重复运行任意遍、任意组合，结果必须逐字节
一致且统计全零。

收敛轮次不随程序规模无界增长：跳转链解析按标号备忘（函数图每个标号只
解一次，环上的标号解析为自身），`dce` 单趟完成可达性与无引用标号删
除，因此包含数千标号与深跳转链的程序也在常数轮内收敛；64 轮上限保证
任何输入都在有限时间内终止。

## 统计报告

`Report` 给出每遍的删除指令数与加权执行成本（`DIV/MOD/PRINT` 等权重更高，
见 `ir.Op.Cost`）变化，以及总轮数、是否稳定、总删除数与总成本变化。
成本是静态加权模型，用于比较同一程序优化前后的相对收益。统计口径覆盖
运行中实际发生的**全部**变换：`dce` 删除的标号同样计入删除数，因此
`TotalRemoved` 恒等于输出相对输入的指令数差（标号也算指令），且等于各
轮各 pass 删除数之和；不存在未计入统计的删除。

## 命令行

```sh
go run ./cmd/optbc parse examples/factorial.bc
go run ./cmd/optbc run   examples/factorial.bc
go run ./cmd/optbc opt   -stats -verify examples/factorial.bc
go run ./cmd/optbc opt   -passes constfold,jump -o out.bc examples/factorial.bc
```

- 解析失败退出码 2；优化失败回退退出码 3；`-verify` 发现行为差异退出码 4。
- `-verify` 在参考解释器上对比优化前后的返回值、PRINT 输出与异常（含源行）。
- `run`/`opt -verify -trace` 会向 stderr 输出单步轨迹（函数、pc、源行）。
